# Routing and decision boundaries

Choose one primary workflow by the requested product and dominant expensive stage, not by isolated node names. Load a second workflow only when the output genuinely crosses domains, such as RBD followed by VAT.

| Primary intent | Workflow | Common secondary route |
|---|---|---|
| Modules along curves | `curve-instancing` | `vellum-settle` for cable relaxation |
| Growth over a surface | `surface-growth` | `pivot-painter` for animated vegetation |
| Footprint or data-driven assembly | `modular-generation` | `curve-instancing` for borders and roof modules |
| Static settled cloth or cables | `vellum-settle` | engine material/export contract |
| Fracture, stacks, or destruction | `rbd-destruction` | `realtime-animation` for VAT |
| Smoke texture production | `pyro-flipbook` | none unless the user requests scene rendering |
| Character or simulation playback in-engine | `realtime-animation` | `rbd-destruction` for rigid VAT sources |
| Hierarchical vegetation deformation | `pivot-painter` | `surface-growth` for source generation |

Do not force a workflow route for scene inspection, a single parameter edit, documentation lookup, MCP server development, or an unrelated rendering task.

When route confidence is low, inspect the target outputs and existing network first. Prefer a bounded general plan to an incorrect mature recipe.
